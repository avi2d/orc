# Vision

One chat runs every agent task across every machine and reports back what each one did.
It serves a captain who directs fleets of AI workers from one place instead of tending each machine.
It owns the loop from backlog to dashboard: a task waits, a machine with room runs it, the captain watches it land.

## Prove it runs

- A change lands with the run that exercises it, never the build that compiles it, and the proof costs a run every time.

## One name for one thing

- Panels, chat output and docs call the same thing by the same name, and a rename reaches every surface in the same change.

## The captain decides

- Orc opens the proposal and records the refusal, and only the captain merges, pushes or deletes, and that caution costs a click on every landing.

## Small units that each end in a check

- Work ships as one edit with its check, never a sweep verified once at the end, and the sequencing costs patience on large efforts.

## Scope

- Agent runtimes belong to Pi, no-mistakes and the model providers, and orc schedules their work without reimplementing them.
- Machine setup belongs to the shell and the OS, and orc only asks a machine with room to take the next task.

A change aligns when it shortens the path from saying what needs doing to seeing it done.
A change should be resisted when it adds a surface the loop from backlog to dashboard does not need.
